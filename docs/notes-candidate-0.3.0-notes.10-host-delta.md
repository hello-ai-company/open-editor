# .10 host integration delta

Public props, authorization, canonical commit receipts, storage formats and writer/session APIs remain compatible with .9. Install the new local artifacts independently; do not overwrite .9 acceptance artifacts. PersonalAI host installation has not been performed by this task.

The host supplies the actual available width and its own app chrome once. Notes observes its root/owner width; a host must not add a second 268px reserve. Standalone uses the left edge. The example reserves host chrome only with explicit `hostFrame=reference`.

Automatic tree cards portal to body. Their anchor comes directly from getBoundingClientRect (viewport coordinates, including the host offset); do not subtract or add the host offset again. Cards flip/clamp to the viewport. Compact drawers clamp to the supplied Notes owner and viewport. Host pages should avoid transformed ancestors around fixed overlays. The explicit NotesPagePreview public drawer is still available separately.

Host .9 diagnosis: desktop body/rail overlap was not reproduced, but embedded1100 had a cramped 226px body, and embedded840 had a fixed drawer at x12 over the PA sidebar. OE .10 synthetic offset tests verify no body overflow and a drawer at x280 after a simulated 268px host reserve. This is simulation evidence, not live host acceptance. Native zoom/IME/Safari and real PersonalAI integration must still be verified by the host owner.

Metadata, cover/upload/provider configuration, DB schemas/rows, legacy preservation, Secretary review/Undo and original59 feature acceptance remain host-bound migration work. This visual polish does not accept those features or authorize deleting the original Notes implementation.
